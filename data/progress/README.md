# Sample contractor documents

Fictional documents for the progress-verification demo, generated by
`backend/scripts/make_progress_samples.py` (run from `backend/` with
`poetry run python -m scripts.make_progress_samples`). Every page carries a
"SAMPLE DATA" footer. Report date: 15 November 2026.

Each stadium has one monthly progress report (an executive summary with an
overall figure and a figure per package) and one detailed plan per scope
element (activities with budget weights, planned dates and actual completion).
Aramco's contractor uses a different template (column names and date format)
from the other two.

| Folder | Stadium | Reported | Plans add up to | Planned by now | Expected finding |
|---|---|---|---|---|---|
| `preloaded/aramco` | Aramco Stadium | 88% | 86.8% | 88.7% | Supported |
| `preloaded/prince-faisal-bin-fahad` | Prince Faisal bin Fahad | 58% | 57.4% | 71.1% | Behind plan |
| `to-upload/king-fahad-sports-city` | King Fahad Sports City | 70% | 52.1% | 69.7% | Overstated |

The King Fahad claim of 70% matches what was *planned* by the report date, not
what was done: floodlighting is reported at 75% but its plan shows 40%.

`revised/kfsc-floodlighting-plan-rev-D.pdf` is a later floodlighting plan
(60% complete). Uploading it supersedes rev C; the recalculated figure rises to
58.4%, still overstated.

"Load sample documents" on the Intake page files and checks the `preloaded`
folders. Drag the `to-upload` and `revised` files onto the page during a demo.
`expected.json` holds the figures the generator computed, used by the backend
tests.

`offline-readings.json` is what the backend pipeline reads from each sample
file (its filing proposal and extracted figures), exported by
`poetry run python -m scripts.export_offline_intake` from `backend/`. When the
backend isn't running, the Intake page uses it as an **offline demo**: only
these files can be added, the arithmetic runs in the browser with the same
rules, and the page says it is offline. Re-export after regenerating samples.
